## A1-2. Who blocks the session on aifoundry1, as the pinned code does it

**The words.** E164.md § Card rules and budget: "another user's idle login does not block (D1), another user on this card or any other
user's device process does (exit 3, never retried)". The header comment of `block_e164.sh` says the same.

**What the code does.** `block_e164.sh`'s `others_present` (lines 28-39, E157's override, unchanged and pinned in `harness-e164.json`)
runs on aifoundry1 with `V3_DEVICE=1` (always: `lib.sh` refuses aifoundry1 without it). It builds the other-user process list only when
`V3_DEVICE` is unset, so it never looks at processes. It blocks when `et-holders` shows card 1's device node (`/dev/et1_…`) or lock
(`lock:etsoc-shire1.lock`) held by a login other than ours, and when `et-holders` cannot be read (it fails closed). The two functions were
run on the same fixtures (`logs/selftest-notes.txt` § 3):

| fixture | E164's code (`block_e164.sh`) | `lib.sh`'s rule (A3) |
|---|---|---|
| another user holds card 1's node, or its lock | blocks | blocks |
| another user holds card 0's node, or its lock | **does not block** | blocks |
| another user's device process, holding no node | **does not block** | blocks |
| a CI job running (`Runner.Worker`) | **does not block** | blocks |
| `et-holders` unreadable | blocks | does not block |
| nobody, or only our own holder | does not block | does not block |

So another user's work on card 0, or a device process or CI job of another user that holds no card-1 node or lock, does not block E164. That
is looser than E164.md's sentence and than `lib.sh`'s A3 rule. It is the rule E157 ran under on this card, and it matches the lab's "one
person per card".

**The amendment.** E164.md's sentence reads: **another user's idle login does not block (D1). Another user holding card 1's device nodes
or its lock blocks, and so does an unreadable `et-holders` (exit 3, never retried). Another user's work on card 0, and a device process
or CI job of another user holding no card-1 node or lock, do not block.** `block_e164.sh` stays as committed. A stricter rule would need a re-pinning
amendment before the claim, and none is made.

**On the day, whether card 0 was in use is recorded, without names.** The corrected launch, `box/launch_e164_a1.sh`, writes
`build/e164/holders-at-launch.txt`: holder counts on each card, ours and another user's, other users' device processes and CI jobs. The
corrected collector, `collect_e164_a1.sh`, writes `logs/et-who-summary.txt`: every et-who reading of the session, counted by card. The
records state both. The launch also refuses (exit 3) if anything holds card 1, or anything of ours is on either card, before the session's
opening config read touches the card (README note § 1).
