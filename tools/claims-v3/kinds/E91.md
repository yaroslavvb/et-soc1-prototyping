# E91: the real tensors' energy replicated on aifoundry1 card 1 (Q130, 600 MHz, E82's frame)

*Pre-registered Sat 31 Oct 2026 (week 44), on the Intel, before the Discord claim of card 1 and the first launch, in
Q130's evening round (lane `a1c1-e91-real-replicate`). The frozen numbers are in
[`predictions-e91.json`](predictions-e91.json), written by [`make_predictions_e91.py`](make_predictions_e91.py) from the
committed sources it names (every number copied, never retyped; each source checked by sha256) and committed with this
file. Any change after this commit goes in the Amendments section at the end, dated, before the data it touches; no
band moves. Card: **aifoundry1 card 1 only** (`V3_DEVICE=1` → `ET_DEVICES=1`, `aifoundry1-c1`,
`/run/lock/etsoc-shire1.lock`), 600 MHz, ~499 mV, TDP 65 W and threshold 65 °C as read (never set), firmware release
1.4.0 (E82 A1). E91 writes no knob: no governor move, no TDP, threshold or clock set, no reset, no `--reset-ms`.*

**The question.** E86 (registration `190c1ac4`, data `a3c0b60d`) measured Q130(n)'s nine real GPT-2 small tiles on
aifoundry3 card 0: real fp32 cost 0.983–0.994 of random fp32, real fp16 0.971–0.996 of random fp16, real int8
0.782–0.888 of uniform random int8, every tile inside Q130(n)'s intervals. Is that a property of the chip or of one
card? E91 runs **E86's pass, E86's code and E78's reduction** on a second card of the same chip, the card E82 measured
E78's 51 kinds on (card scale 1.031 against aifoundry3) and E88 measured the result path on this evening. It scores
Q130(n)'s frozen predictions on card 1 (Amendment 1's E91 column) and the cross-card rules E82 registered, on the
real tiles.

## Decision rules

All on D at the primary reduction (dips removed, leakage `auto`); each verdict at the five arms (dips kept; leakage
0.1994, 0.545, 0.3803, 0) is reported beside, and a verdict that moves is marked arm-sensitive. **Fewer than 4 kept
passes: every rule NOT SCORED. A quantity with fewer than 3 kept passes is unresolved and never counts as inside or
PASS.** Ref is each type's random kind (fp32/fp16 randn, int8 full), per pass the mean of its three runs. 95%
intervals are t(0.975, n−1) × SE over passes.

**Primary rules: E86's, scored by `score_e86.score()` unchanged on card 1's numbers** (thresholds copied from
`predictions-e86.json`):

## Self-test

`selftest_e91.py` writes five synthetic card-1 passes with E78's own generator after installing E86's items and order
(card 1's 65 / 65 reads, 499 mV), injects card 1's meter artifact (pairs of `board_w` samples 8–14 W low inside run
windows, 8 samples a pass), and runs `reduce_e91.py` (primary, dips kept, leakage 0.545) and `score_e91.py` on two
worlds. "Shared" (E78 kinds at E82's card-1 D, real tiles at E86's D / E82's scale): the primary removes every injected
sample and keeps all five passes (the dips-kept arm keeps none), recovers D within 0.088 W, R1 9 of 9, R2, R5, S1 and
X4 pass, X3 fails at the median 1.033. "Unshared" (real tiles at E86's D × 1.03): X4 fails (0.975), R1 still passes
([`selftest_e91.txt`](selftest_e91.txt); 15 of 15 checks). Nothing it prints is data.

## Card budget

**At most 35 card-minutes, from the claim post to its release edit**, including the smoke and every heating gate.
`queue_e86.sh` runs unchanged with `E86_BUDGET_MIN=30`, `E86_DEADLINE=22:25`, `E86_FIRST_S=390` (set by
`run_e91.sh go`): a pass starts only if its projected end (the longest measured pass; 390 s before the first one ends)
is inside 30 card-minutes of the queue's start and before 22:25 PDT; a pass in flight is never cut. At E88's 9.1 s a
run on this card a 34-run pass takes about 5.4 min, so five passes fit, four if a pass takes more than ~5.6 min. The
config reads are the blocks' own (each block reads `ettelem config` at both ends under the lock); no separate read.
No session starts after 21:45 PDT; every run ends by 22:30. The claim is posted for 1 h (35 min plus a margin, rounded
up to the half hour).

## How to run it (for this lane)

On the Intel, after this commit is on origin/main: `rsync -a --exclude __pycache__ tools/claims-v3/kinds/
aifoundry1:nekko/tools/claims-v3/kinds/`. On aifoundry1, from `~/nekko`:

```bash
bash tools/claims-v3/kinds/run_e91.sh setup      # no device access (done once before this commit; repeat after the sync)
# -> post the #community-lab claim: "using aifoundry1 card 1 for 1 h, until ~HH:MM PDT"
bash tools/claims-v3/kinds/run_e91.sh smoke      # pass 9101: seven 2 s runs; cycles/op 546 / 546 / 318, 600 MHz, 65/65 reads
bash tools/claims-v3/kinds/run_e91.sh go 9110 6  # detached; the budget rule decides how many of the six run
bash tools/claims-v3/kinds/run_e91.sh status     # bounded checks only
```

Then copy `build/claims-v3/aifoundry1-c1/kinds/p91*`, `kinds-smoke/p9101` and `build/e91-*.log` to the Intel and run
`PY=/usr/bin/python3 nice -n 10 bash tools/claims-v3/kinds/collect_e91.sh 'p91[1-9][0-9]' <copy>`; copy
`build/e91-out/2026-10-31-e91-real-tensors-aifoundry1/` to `docs/reports/data/`, write its README (results first;
registered against happened; departures dated), and release the claim by editing it.
