# E86: the real tensors' energy (Q130, aifoundry3 card 0, 600 MHz)

*Pre-registered Sat 31 Oct 2026 (week 44), on the Intel, before the Discord claim and the first launch, in Q130's
evening round. The frozen numbers are in [`predictions-e86.json`](predictions-e86.json), written by
[`make_predictions_e86.py`](make_predictions_e86.py) from the committed sources it names (every number copied, never
retyped) and committed with this file. Any change after this commit goes in the Amendments section at the end, dated,
before the data it touches; no band moves. Card: **aifoundry3 card 0 only**, 600 MHz, ~522 mV, TDP 0 and threshold
65 °C as read (never set). E86 writes no knob: no governor move, no TDP, threshold or clock set, no reset, no
`--reset-ms`.*

**The question.** E78 measured what multiplying 51 synthetic kinds of numbers costs on this card. What does a real
model's numbers cost? Q130(n) cut nine tiles from GPT-2 small (layer 0's MLP up-projection, layer 6's MLP
down-projection, layer 6's attention QK^T; each in fp32, fp16 and int8) and froze a prediction for each before any
card ran them. E86 runs the nine **beside E78's anchors and comparison kinds in every pass**, on E78's card, clock,
protocol, code and reduction, so each real tile gets a measured switching power, energy per operation and heat
column, and Q130(n)'s predictions get scored: is each tile inside the predictor's interval, and do the real tiles sit
where the predictor puts them against random data and against E78's synthetic "neural-network-like" kinds?

## Decision rules

All on D at the primary leakage slope; each verdict at the three arms is reported beside, and a verdict that moves
between arms is marked slope-sensitive. **Fewer than 4 kept passes: every rule NOT SCORED. A quantity with fewer than
3 kept passes is unresolved and never counts as inside or PASS.** "Ref" is each type's random kind (fp32/fp16 randn,
int8 full); per pass its value is the mean of its three runs. 95% intervals are t(0.975, n−1) × SE over passes.

**Primary rules: Q130(n)'s frozen predictions.**

| | rule | threshold | why this value, before the data |
|---|---|---|---|
| **E86-R1** intervals | each real tile's D inside its Amendment 1 scoring interval | **≥ 7 of the 9** (needs ≥ 8 resolved) | the interval is a nested-LOO 95% interval (Amendment 1 (a)); 7 of 9 is E87-R4's count, so the three real-tile lanes score alike. Beside it: the count inside the frozen intervals, and the count whose own 95% interval overlaps |
| **E86-R2** accuracy | rms over a format's three tiles of (D − frozen point) | **fp32 ≤ 2.0, fp16 ≤ 2.0, int8 ≤ 1.0 W**, each format | E78-R2's bounds, copied from `predictions-e78.json`; Amendment 1 expects a nested-LOO rms of 1.125 / 1.089 / 0.606 W (reported beside, with the mean error) |

**Secondary rule: like with like.**

| | rule | threshold | why |
|---|---|---|---|
| **E86-S1** | per tile, the per-pass ratio D(real)/D(ref), averaged over passes, inside the ratio interval (Amendment 1's scoring interval divided by E78's D(ref)) | **≥ 7 of the 9** (needs ≥ 8 resolved) | cancels the session's scale, as the verification behind Amendment 1 recommends (`amendment-1.json` › `like_with_like`; E87-S3 the same on aifoundry2). Beside it: the frozen ratio intervals, and the anchored D = ratio × E78's D(ref) |

**Reported, never a verdict:** for every real tile and comparison kind, S (switching over idle), pJ per op, per MAC
(÷ 4,096 / 8,192 / 16,384) and per flop (fp32, fp16) from S and from D, the heat column ΔT, D32, the rail arm, the
ratios to ref and to the comparison kind; E78-R5's checks (idle consistency median |S − S0 − D| ≤ 0.15 W; the rail
lag re-fitted, median in [0.80, 1.15] s; duty in [0.990, 1.000]; carry-over |β| ≤ 0.01 W/W or < 3 SE); every gate
failure; each pass's configuration reads. **Failures are reported as failures**, with the measured value beside the
band. No band moves after this commit.

**What the rules cannot say** (Q130(n)'s open issues that bind here): the predictor is a post-hoc fit to E78's kinds
whose terms are not mechanisms (it prices B-side flips at 0, which E65 contradicts), so a miss may come from that;
int8's bus counts are provisional (the reconstructed TIMA stream; its gated fraction, 0 for every real tile, is
not); int8 uses one simple calibration (four others give 0.735–0.869× of full); the int8 `l6_attn_qk` window lies in
the causally masked triangle (a dense QK^T computes it, a causal kernel does not); the fp16 tiles are fp32
activations rounded to fp16. One tile a cell is a draw: E86 measures these nine tiles, not GPT-2 in general.

## Self-test

`selftest_e86.py` writes six synthetic passes with E78's own generator (`selftest_e78.make_pass`) after installing
E86's items and order, so every pass is E86's 32-run order, and runs `reduce_e86.py` and `score_e86.py` on two
worlds. With the frozen points as the truth, the reduction recovers every real tile and reference cell to 0.107 W
and every rule passes; with real fp32/fp16 at 1.015× randn and int8 at 0.95× full, E86-R3 fails in every format
while R1 still passes (the intervals are wide) ([`selftest_e86.txt`](selftest_e86.txt)). `collect_e86.sh` was run end
to end over the synthetic passes, every leakage arm included. Nothing it prints is data.

## Card budget

**At most 40 card-minutes, including the smoke, the session's configuration reads and the heating gates.**
Expected about 37: the smoke ~1.5 min, then passes of ~5.8 min (34 runs with the burn-in at E78's measured 9.4–9.7 s
a run, plus the block's sampler and reads) with 15 s between them. `queue_e86.sh` starts a pass only if its projected
end (the longest measured pass; 390 s before the first one ends) is inside **36** card-minutes of the queue's start
and before **22:25 PDT**; a pass in flight is never cut. No session starts after 21:45 PDT; every run ends by 22:30.
The claim is posted for the budget plus a margin, as CONTEXT §4 says.

## How to run it (for this lane)

On the Intel, after this commit is on origin/main: `rsync -a --exclude __pycache__ tools/claims-v3/kinds/
aifoundry3:aifoundry/tools/claims-v3/kinds/` (the real tiles travel with it; `run_e86.sh setup` checks every one by
sha256). On aifoundry3, from `~/aifoundry`:

```bash
bash tools/claims-v3/kinds/run_e86.sh setup      # no device access: the reused files and E86's against the freeze,
                                                 # the tiles, the binary's strings, the plan, a V3_DRY pass
# -> post the #community-lab claim (one line, "for <N> h, until ~HH:MM PDT"), THEN read `ettelem config` once
#    under the card lock (timeout 10): TDP 0, threshold 65
bash tools/claims-v3/kinds/run_e86.sh smoke      # pass 8601: seven 2 s runs; cycles/op 546 / 546 / 318, ok
bash tools/claims-v3/kinds/run_e86.sh go 8610 6  # detached; the budget rule decides how many of the six run
bash tools/claims-v3/kinds/run_e86.sh status     # bounded checks only
```

Then copy `build/claims-v3/aifoundry3/kinds/p86*` and `kinds-smoke/p8601` with the logs to the Intel and run
`PY=/usr/bin/python3 nice -n 10 bash tools/claims-v3/kinds/collect_e86.sh 'p86[1-9][0-9]' <copy>`; copy
`build/e86-out/2026-10-31-e86-real-tensors-energy/` to `docs/reports/data/`, write its README (results first;
registered against happened; departures dated), and release the claim by editing it.
