## The set-aside rule (written here; `predictions-e131.json` › `set_aside_rule`)

**Why a pass is set aside on this card.** Over the 15 committed primary reductions of E78-frame passes on card 1 (73 passes), 6 passes were set
aside, every one by an anchor gate of one or two formats: four by a zeros line's straight-line departure (0.253–0.297 W against 0.25 W), two by a
random anchor's span in E82's dips-kept primary; none by the tie, by failed runs or by a config read
([`history-card1.txt`](../../../docs/reports/data/2026-11-02-e131-real-tiles-card1/desk/history-card1.txt)). So about one pass in twelve, and E95's
pass, with its 18 anchor runs, gives every gate its chance.

- **S1, the primary.** E78's pass gates unchanged: each format's zeros line departs ≤ 0.25 W from its straight line and spans ≤ 0.60 W; each
  random anchor spans ≤ 1.0 W; the π tie drifts ≤ 0.60 W; at most 2 failed runs; card 1's config read. **It carries every verdict if it keeps at
  least 3 passes** (E95's convention).
- **S2, only if S1 keeps fewer than 3.** A pass set aside **only** by the π tie's drift is restored whole: π enters no claim and no cross-card
  rule, only the reported session tie.
- **S3, only if S1 and S2 keep fewer than 3.** A pass set aside only by the anchor gates of one or two formats (their zeros line's departure or
  span, their random anchor's span; the tie as in S2) is restored **for the other formats' items**; the failing formats' items in that pass,
  anchors included, stay out. Each format's D is over its own zeros line and its r over its own random anchor, so a gate on one format's anchors
  says nothing of another's. **A claim is scored only if every format it reads has at least 3 passes in the reading** (`claims_types`: C1–C4 fp32
  and fp16; C5–C8 int8; C9, C10 fp32; C11 fp16; C12 all three), else it reads NOT SCORED; a pairing across formats (C4) uses only passes that
  keep both. The cross-card rules keep E112(b)'s own resolution limits (a format below 75% resolved: X1 NOT SCORED; X4 needs 18 eligible tiles
  resolved, X5 26 of 33).
- **Never restored:** a pass with more than 2 failed runs, a pass whose config read is not card 1's 65/65, a block that did not end ok, an
  `.attempt-*` directory.
- **Where the restored values come from:** `reduce_e131.py --relax-anchors` (the anchor and tie gates raised to 99 W, every other gate E78's) at
  the same frozen slope. With a fixed slope each pass's reduction does not depend on the others, so its per-pass values equal the primary's for every
  pass both keep (self-test D: 1,120 values on E112(b)'s passes, max difference 0).
- **Fewer than 3 passes after S3:** every claim and cross-card rule NOT SCORED. **No pass is added after any reduction is read, and no pass is
  chosen after the fact.** All three readings are always reported, and every verdict names the reading that carries it.

*Desk run on E112(b)'s published passes (self-test D; labelled, E112(b)'s data, never E131's):* at 0.2414 W/°C S1 keeps 11250 and 11251 and sets
11252 aside (`fp32.zeros` −0.253 W); S2 restores nothing; S3 restores 11252 for fp16 and int8, so the int8 and fp16 claims are scored on three passes
(C5 INCONCLUSIVE, C6 PASS, C7 INCONCLUSIVE, C8 PASS, C11 INCONCLUSIVE) and every claim that reads fp32, and the three cross-card rules, read NOT SCORED.
