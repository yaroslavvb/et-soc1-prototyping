## 3. The sessions that must carry a C log, stricter at the collection (the verifier's fault 7)

**What it found.** E173.md registers the list's derivation: the queue's record (`queue.jsonl` › `session_start`) and each session's
`launches.jsonl` work launches. The rule is `p8gov.required_c_logs`, the scorer's own; `cclist_q142kg.py` uses it at the collection. Lost records
can drop a session from that list. The verifier's probes:
- V7: a copy with no `queue.jsonl` and no smoke directory drops smoke;
- V8: a listed s1 whose `launches.jsonl` is lost counts no work launch and drops out.

In both, the runbook's gate and the scorer's coverage check passed. Every rule would then read NOT SCORED, never a false score, but the step would
say "collected and scored". That is the class of the Q142 critic's fault 3, which the list was registered to close.

**Registered here, before any E173 data.** The card day collects E173 with `box/step_e173_v2.sh collect` (committed next, in the kits' fix
commit). Its C-log gate (`../q142kg-runbook/rb_common_v2.sh`) reads [`../q142kg-runbook/cclist_q142kg_v2.py`](../q142kg-runbook/cclist_q142kg_v2.py):
1. the queue's record (`queue.jsonl` or `.gz`) must be in the collected runs dir; without it the list cannot be read, and the collection stops
   (MISSING-QUEUE; the step's 14);
2. the sessions read are those the queue's record started and every directory there with a session's name (smoke, stoptest-board,
   stoptest-die, s1-s6);
3. a session must carry a C log and a finished check of it when v1's rule requires it, or when it is not a dry session and:
   - (a) for smoke, stoptest-board and s1-s6: its `runs.jsonl` holds a run record;
   - (b) the same, when its `launches.jsonl` is missing: the queue's `session_end` for it gives more than 0 card-minutes;
   - (c) for stoptest-board: the queue's `session_end` gives the board stop (`safety:board ...`), which fires only inside its launch;
   - (d) for a session directory v1 does not read (one the queue's record does not start, other than smoke, stoptest-board and s1): v1's
     own rule, a work launch in its `launches.jsonl`;
4. stoptest-die keeps v1's rule (only if it ran a work launch); a dry session needs none. Then v3.1's `ccdone_q142s.py` reads every listed check
   (there, with ccheck.py's summary, written by this collection), as before.

**What does not change.** The scorer's own refusal stays as registered: `score_e173.py`'s exit 5 through `p8gov.required_c_logs`. v2's list only
adds sessions to v1's, so it can stop a collection and never adds a score. A session it adds must carry what E173.md's list already asks of the
sessions it names: a C log and a finished check. On the parents' committed sessions (E165 on aifoundry2, E170 on card 0) v2's list equals v1's
