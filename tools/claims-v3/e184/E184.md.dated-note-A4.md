## A4-1. What was wrong

A3-3 item 1 made **any JSON object** the session's own read, "checked as registered"; only a file absent, empty or holding no JSON object
was missing. Its code checked the two edges together, and only when both reads were non-empty (`reduce_e184_v3.py` lines 159-172;
`reduce_e184_v2.py` had the same test). Four readings followed, all latent and all before any datum:

| the reads | A3-3 as coded | what A3-3 means (and A4 now says) |
|---|---|---|
| a partial read (a failed GET's `null`, or no `minion_mhz`) beside a good step-7 read | MOVED: the arm NOT SCORED | a failed read is an absence of evidence: MISSING, replaced |
| an empty `{}` at one edge and a MOVED read at the other (the verifier's H4, H5) | the gate holds; end to end the arm scores as registered | a moved read is fatal (A3-3 item 5) |
| an empty read replaced by a step-7 file that is `{}` (H15) | the gate holds, unchecked | the replacement is checked as the session's own would be (item 4) |
| arm B, TDP and threshold `null` at both ends (H6) | the gate holds (`None == None`) | "the same TDP and threshold at both ends" is not shown |

The first reading voids an arm for a reader's failed GET when a good read sits beside it; the other three let a reading A3-3 calls fatal
or unchecked pass. Both directions were wrong, so A3-3's reading of a read changes here.

## A4-2. The rule (it replaces A3-3 item 1's test and the word "moved" in item 5; items 2-4 stand)

1. **The three keys** are `tdp_w`, `temp_threshold_c` and `minion_mhz`. A key is **present** when the read holds it with a value that is not
   `null`. A JSON object that is not a dry read and has all three present is a **complete** read. One that lacks any of them, or holds
   `null` for any, is a **failed** read; an empty `{}` is one.
2. **A session read is MISSING** when its attempt was recorded (its `.time` file) and its file is absent, empty, holds no JSON object, or
   holds a failed read. A MISSING read is replaced as A3-3 items 2-4 say (the newest step-7 read of the arm in the 90 minutes before T0 for
   a start; the oldest in the 30 minutes after the end read's attempt for an end) and named in the scored files as a departure. A read
   whose attempt was never recorded is never replaced.
3. **A step-7 file is a read only when it is complete.** A failed or empty step-7 file is passed over, and the window's next complete read
   is taken.
4. **A complete read is checked on its own, whatever the other edge holds** (the session's own read, or its replacement): aifoundry3 TDP
   0 W, 65 C, 600 MHz; card 1 600 MHz, and once both edges hold a read, the same TDP and the same threshold at both. A value matches a
   registered number only when it is a JSON number (`true` and `false` are not numbers). **A complete read not as registered is MOVED:**
   the arm is NOT SCORED whatever step 7 reads.
5. **Still NOT SCORED, as A3-3 says:** a moved read; a dry read in a real session's file; a missing read whose attempt was never recorded;
   a missing read with no complete step-7 read in its window; a replacement that is complete and not as registered.

## A4-4. Why it carries no bias

- It is decided before any E184 datum, and no datum can inform it: a config read opens no pass and measures no power.
- It moves the gate only on the reads' form. It scores an arm v3 would have voided only when a complete step-7 read in A3-3's window reads
  as registered, and it voids an arm v3 would have scored only when a complete read is not as registered, or no complete read exists at an
  edge. Neither depends on any measured watt, step or verdict.
- The windows, the replacement's check and the departure's record are A3-3's.
