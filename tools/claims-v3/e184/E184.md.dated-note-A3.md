| base noise | 1.1e-6 | 1.1e-4 | 7.4e-4 | 0.004 | **0.016** | 0.053 | 0.135 | 0.280 | **0.474** | **0.675** |
| twice the noise | 0.015 | 0.044 | 0.071 | 0.110 | **0.162** | 0.227 | 0.306 | 0.394 | **0.488** | **0.583** |

The chance reaches 0.05 at a gain of 1.60 (base) or 1.22 (twice the noise), and 0.5 at 1.91 (both). The verifier's own figures at 1.5, 1.9 and
2.0 agree: 0.016 / 0.47 / 0.68 and 0.16 / 0.49 / 0.58.

**The decision: the band is kept, and this clause says what it costs.**

  above 1. So "E184-P's registered powers stand" stays true, and A2-7 is corrected to say it holds for gains of at most 1.
- A small-step gain of 1.6 or more, where the chance passes 0.05 at base noise, is far outside E184-P's forecast (LINEAR, 1 +- 0.12) and on the

## A3-3. A missing config read is replaced by step 7's read; a moved one still voids the arm (the verifier's fault 3)

**What was wrong.** Kit note 1's session gate (`reduce_e184_v2.session_gate`) reads a start or end config read that came back EMPTY the
same as one that MOVED: either way every rule of the arm is NOT SCORED. Each read is one `flock -n <card lock> timeout 10 <guard> config`,
never retried, and the session goes on when it is empty, so a lock another process takes in that second, or one slow reader, would leave a
whole arm (about 2 h of card time on aifoundry3) unscorable after the card time is spent. A missing read is an absence of evidence, which a
read taken just before or after the session supplies; a moved read is evidence that the card's configuration changed, and stays fatal. The
per-pass 600 MHz re-read (kit note 1 section 2) already checks the clock in every pass. So the gate as written was wrong for a missing read,
and this clause changes it, before any datum.

**The rule** (kit note 2's `reduce_e184_v3.py` implements it; nothing else in the session gate changes):
1. A session's config read is **missing** when the session recorded its attempt (`config-<arm>-t<T0>-<edge>.json.time`, which the session
   writes after every attempt) and its file is absent, empty or holds no JSON object. A read that is a JSON object is the session's own and
   is checked as registered, as before.
2. **Step 7's read** is the config read of the runbook's step 7 (kit note 2's `rb/s09_reads_e184_v2.sh`: the same READ through the same
   telemetry guard, under the card's lock, timeout 10, as v1's step), written on the box with the box's own clock as
   `build/e184/config-<arm>-step7-<epoch>.json` and copied back to the desk with the session's own files. Step 7 runs before the launch,
   as registered, **and again right after step 10 reads this T0's session end, before the release, every time** (a few seconds, READ
   only). Like v1's, it refuses beside a session of ours; the second run also refuses unless this T0's log on the box has its end line.
3. A missing **start** read is replaced by the **newest** step-7 read of that arm taken in the **90 minutes before T0**; a missing **end**
   read by the **oldest** step-7 read taken in the **30 minutes after the end read's attempt**. Between such a read and the session nothing
   of ours touches the card's configuration: step 8's pass is V3_DRY and opens no device, step 7 refuses beside a session of ours, and no
   file of the kit sets anything.
4. The replacement is checked exactly as the session's own read would be (aifoundry3: TDP 0 W, 65 C, 600 MHz; card 1: 600 MHz, and the same
   TDP and threshold at both ends), and it is named in the reduced and scored files as a **departure** (the edge, the empty file, the
   step-7 read used and its time). The arm is then scored as registered.
5. **Still NOT SCORED:** a moved read (present and not as registered), whatever step 7 reads; a dry read in a real session's file; a
   missing read whose attempt was never recorded (the session did not reach it); a missing read with no step-7 read in its window; a
   replacement that is itself not as registered.

## A3-4. A2-4's level filter covers E184-C (the verifier's fault 2)

A2-4 registers that "a level with fewer than 4 kept quads is left out of its rule", for every rule. The scorer (v1, and v2 after A2) left
E184-C's scan levels unfiltered: any level with one readable quad counted toward A2-4's 10. **The registration governs.** Kit note 2's
`score_e184_v3.py` leaves every scan level besides the reference with fewer than 4 kept quads out of A2-1's fit, out of the reference
reading's median and out of the reported registered statistic, and counts only the levels kept toward the 10; the reference level's quads
are set aside by A2-1 whatever their number (read as the scan's own null, reported). With 12 quads a level planned, it binds only after
heavy set-asides. This changes no rule: it makes the code read A2-4 as written.
