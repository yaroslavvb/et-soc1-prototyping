## 1. A train's half-width, by the registered statistic (the verifier's fault 2)

E183.md quotes a 52-process train's 95% half-width as about +-0.0098 W at E180's noise (BASE) and 0.0196 W at twice it (DOUBLED). It does
so in section 0, in section 6's sizing paragraph and in section 6's "design's figures". It quotes T5's as +-0.0050 W in section 0 and as
0.0050 / 0.0100 W in section 6's sizing paragraph. **Those are the plan's z values**: 1.96 sigma_q / sqrt(n_q), which are `plan-e183.json`'s
`half_width_base_w` (0.00981; T5 0.00498) and `half_width_doubled_w` (0.01961; T5 0.00995). The registered statistic (section 5.1, E182's
`e182_stats.py`) is the mean over units with t(0.975, units - 1). Read that way ([`logs/note1-checks-e183.txt`](logs/note1-checks-e183.txt),
part 2: 4,000 simulated sessions a level in `power_e183.py`'s own draw, seed 18399):

| train | units | the plan's z value, BASE / DOUBLED | **the registered statistic's half-width, BASE / DOUBLED** | plug-in t(0.975, units - 1) sigma / sqrt(quads) |
|---|---:|---:|---:|---:|
| T1-T4 and T6 (52 processes, 156 quads) | 26 | 0.0098 / 0.0196 W | **about 0.0103 / 0.0205 W** (medians 0.0102-0.0103 / 0.0204-0.0206) | 0.0103 / 0.0206 W |
| T5 (202 processes, 606 quads) | 101 | 0.0050 / 0.0100 W | **about 0.0051 / 0.0101 W** (medians 0.0050-0.0051 / 0.0101; `power-e183.json`: 0.005055 / 0.010105) | 0.0050 / 0.0101 W |

- **Quote these.** Each 52-process train reads its pair to about +-0.0103 W (BASE) and 0.0205 W (DOUBLED). T5 reads his pair to about
  +-0.0051 W and 0.0101 W, which section 5.2's E183-HT row already quotes. Never +-0.0098, +-0.0196 or +-0.0050 for the t statistic: those
  are z values. This is the class of E182's "0.0051 W (t), never +-0.0049". b's and c's half-widths (0.0010 / 0.0020 W a bit) were the

## 4. Section 5.1's process rule, as it governs (the verifier's fault 1, nits 6, 7 and 8)

- **A live stop (fault 1).** Section 5.1 registers the rule at the level of the process: "A process during which a stop fired ... gives no
  value." That governs a train block in which a live stop fired. The process the stop names gives no value. The processes before it keep
  their values. The processes after it never ran, so they have no records and no value. Section 7's "A stop ends the session; nothing is
  retried" ends the queue, and it voids no earlier process. **The kit as committed did otherwise:** it set such a block aside whole
  (block.json reads `stop`), so its own process rule was never reached. That was a departure from section 5.1's letter, not a choice the
  section left. The kit's note 1 codes section 5.1 (reduce v2). A stop block without its stop.json is set aside, since the process cannot
  be named.
- **Two conditions added to section 5.1's list, registered here before any datum (nits 6 and 8):**
  - a process gives no value when a launch's image (its record's `train_operands`) is not its kind's image, which is the box's own
    post-block test (`check_e183.py`'s `train_faults`). Section 5.1's list already names a kind, an orientation or a number off the plan's
    schedule. The image is what the launch actually loaded, so a process on a wrong image did not run the registered pair;
  - a train block whose block.json `t0_ms` is missing, or earlier than the session's T0, is not this session's datum, and it is set aside.
  
  Neither condition can move a train's estimate in a chosen direction: each removes a process or a block that did not run the
  registered measurement in this session. Both are decided before any datum.
- **E183-TR-N's pool (nit 7).** Section 5.2 registers "every train's quads". That is every reduced train's quads, a NOT SCORED train's among
  them, and not a set-aside block's. The kit codes it so (`score_e183.py`'s `tr_n`, unchanged). KIT.md's "every scored train's quads" was
  the stray word, and the kit's note 1 corrects it. TR-H stays the scored trains' median, as registered.
