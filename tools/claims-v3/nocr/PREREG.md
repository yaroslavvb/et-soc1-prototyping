## Questions

- **R31 (rung 31, `exp-mesh-stops`).** Where are the master shire (32) and the eight memory shires on the mesh? The
  chip diagram draws them from the firmware's NoC map and the DRAM-latency fit
  (`docs/reports/data/2026-09-27-chip-diagram/research/firmware_map.json`), which leaves memory shire 2 a tie and the
  master's grey cell unmeasured.
- **R32 (rung 32, `exp-route-order`).** Does the mesh route x first or y first on marty1885's logical map? Every
  route on the chip diagram and on heat-per-mm assumes x first (fact L104, kind "inferred"). And do replies follow
  the same rule as requests?
- **Q63, second test** (per hop or per mm, through a 1.74-1.80 mm memory-shire column): not run; see the end.

## Method in one paragraph each

**R31.** One hart per compute shire (hart 0 of minion 0) times stock syscalls that make M-mode access another
block's ESRs over the mesh: `SYSCALL_PMC_SC_SAMPLE` (9) on a shire's cache bank and `SYSCALL_PMC_MS_SAMPLE` (10) on a
memory shire. **What each call touches is the compiled firmware's code, not `pmu.c`'s C text**: the ESR pointers in
`pmu.h` are not `volatile`, so the compiler merges the stop's and the start's read-modify-writes. The disassembly of
`sample_sc_pmcs` and `sample_ms_pmcs` (identical code in the three lab hosts' `/opt/et` copies of `MachineMinion.elf`
and in `build/fw-build`): pmc 0 = `ld ctl; sd ctl; ld counter; sd ctl` (**2 loads, 2 stores**); cache-bank pmc 3
(`PMU_SC_ALL`) = `ld ctl; sd ctl | 0x20011` (**1 load, 1 store**); pmc 7 matches no case (**no ESR access**: the
syscall's own cost, the null call). So pmc 0 - pmc 3 and pmc 3 - null are each one load plus one store, and a load's
cost cannot be separated from a store's with these calls. The cards run flashed minion firmware (0.22.0 on
aifoundry1's card 1, 0.23.0 on aifoundry3), which cannot be read off the card; it was built from the same `pmu.c`
and `pmu.h` (et-common-libs 0.22.0 and 0.23.0 equal today's apart from the licence header) with an unknown compiler,
so a registered check (below) tests the access counts on the card before either difference is used. The 32 callers
take turns in 6 M-cycle slots, so one of our calls is on the mesh at a time; each caller's list is padded to a
multiple of 8 entries (timed no-ops, never counted) so that its results fill whole 64 B lines. Per pass: three
launches of 1 warm-up + 8 repetitions over 32 compute targets (pmc 0 and 3), 8 memory shires, and the null calls,
each repetition in its own shuffled order; then one launch of 1 + 16 repetitions on shire 32. Shire 33 (the spare)
is never called; the kernel refuses it. **Background traffic we cannot stop:** the master's stats worker
(`statw.c`, `STATW_SAMPLING_INTERVAL` 1 ms) samples every compute shire's four cache banks and every memory shire's
counters once a millisecond (`SYSCALL_PMC_*_SAMPLE_ALL_INT`), the same `ctl_status` registers our calls stop and
start, so some calls are delayed and read-modify-write races with it are possible (both sides end by starting the
counters, so none is left stopped).

**R32.** The E27 wire kernel (1 KB tensor loads, two in flight, 32 minions of a reader shire streaming a 32 KB slice
of one other shire's scratchpad; `workloads/nocroute`). A *flow* is data moving src -> dst. A read's requests travel
dst -> src, and under dimension-order routing the request path under one order is the reply path under the OTHER
order, reversed. Sets of flows (`sets.json`, generated by `workloads/nocroute/meshmap.py`, which checks every claim
below for replies and requests): five *families* of nested sets (k = 2, 3, 5; rowW k = 2, 3). The row families
(rowE, rowF, rowW) share one directed link on their **replies** under x first, and the reversed link on their
**requests** under y first; the column families (colS, colN) the mirror image. No other directed link carries two
flows' replies, two flows' requests, or a reply of one flow and a request of another, under either order. Two
*positive controls* (three straight flows along one row or one column: replies share one link and requests the
reversed one under either order) and two *negative controls* (no link shared by any packets under either order:
neg1 five one-hop flows, 234 GB/s in all; neg2 four bent flows). Every flow also runs alone. One repeat = one host
process = every solo and every set once, in a shuffled order, 30 M cycles each; three read repeats and three write
repeats per pass. The statistic is **rho = (sum of the set's flows' bytes per cycle) / (sum of the same flows alone,
same repeat)**; a pass's rho is the median over its repeats, and the verdict uses the median over passes. **R32w**
runs the same flows as tensor stores from src into dst's scratchpad: the data then travel as requests and the small
packets (acknowledgements) as replies, so the write verdict is the request order and the read verdict the reply
order. Because each family shares a link under both orders, the order is read from the **contrast** between the
mirrored families: the family whose data share falls further, since a control packet (a request, an
acknowledgement) is registered never to cost a link more than the data it stands for (c <= 1, below).

## Theories and predictions

| # | Theory | Prediction (the rule that decides it is in the next section) |
|---|---|---|
| P1 | T-DIRECT: an ESR call costs a constant plus a term per mesh hop from caller to target, over the same shortest-path mesh as memory traffic | the 992 caller-target pairs of compute shires (own shire excluded) fit C + s x hops with r² >= 0.98 and rms <= max(4, 0.1 s) cycles; the additive caller + target ("via a hub") model fits worse |
| P2 | T-12: each ESR load is one mesh round trip at 12 cycles per hop (600 MHz), like a memory load | the per-hop slope of one load plus one store (pmc 3 - null) is in [10, 14] (stores posted: they add no per-hop cost) or in [20, 28] (stores acknowledged: a second round trip) cycles per hop; s(pmc 0) is then about 24 or 48 |
| P3 | ESR stores: posted, or acknowledged | the same slope says which: [10, 14] posted, [20, 28] acknowledged. An acknowledged store and a 24-cycle-per-hop load with posted stores give the same slope and are not separable with these calls. No preference registered |
| P4 | T-NULL: the null call's cost does not depend on where the caller sits | per-caller medians of the null call within 10 cycles of each other |
| P5 | T-FW-MASTER: shire 32 is the top grey cell (0, 3) (firmware map; the bottom cell (5, 3) is the spare) | among the four grey cells, (0, 3) fits best with a free constant and the slope of P1, rms <= max(6, s/6), next cell worse by >= s/3 |
| P6 | T-FW-MS: memory shire k at (k+1, -1) for k < 4 and (k-3, 6) for k >= 4, one ring outside the grid | each memory shire's best ring cell (one constant common to all eight, slope of P1) is that cell, rms <= max(6, s/6), next cell worse by >= s/3; P6b: memory shire 2 at (3, -1) |
| P7 | T-SAME-SLOPE: memory-shire calls cost the same per hop as cache-bank calls (both are 2 loads + 2 stores) | free-slope fit of the memory-shire calls at the P6 cells within 15% of s |
| P8 | T-XY: replies travel x first (the chip diagram's assumption, L104; Chang infers XY) | read rho: rowE5 and rowF5 <= 0.90, and either every column set >= 0.95 or both column k = 5 sets exceed both row k = 5 sets by >= 0.10; negatives >= 0.95 |
| P9 | T-YX: replies travel y first | the mirror of P8 |
| P10 | T-WIDE: no directed link saturates at up to 170 GB/s | every family set and both positive controls >= 0.95: the order is then not identified |
| P11 | T-ADAPT: minimal adaptive or mixed routing | sets fall in both families with no contrast. Dimension order with control packets as costly as data (c near 1) predicts the same, so this can be refuted (a contrast) but not confirmed |
| P12 | T-SAME-RULE: requests use the replies' order | the write verdict equals the read verdict (the opposite: replies retrace requests) |
| P13 | T-REQ: a read's requests load the reversed links, each costing c of its reply, 0 <= c <= 1 | under the identified order, the family whose requests share falls too (both its k = 5 sets <= 0.90); c is then estimated as the reply family's k = 5 set GB/s over the request family's, and otherwise bounded above by capacity / demand |

Expected sizes for reads (max-min sharing, E27's solo bandwidths as demands, requests weighted by c; `meshmap.py`
prints every set, order, capacity and c). With a link of 102.4 GB/s per direction (four 512-bit lanes at 400 MHz,
the favourite) and x first: rowE5 and rowF5 fall to rho 0.61-0.62, the row k = 3 sets and both positive controls
to 0.88-0.89, the k = 2 sets hold (84 GB/s of demand). The column k = 5 sets hold for c <= 0.6, fall to 0.80 at
c = 0.75 and to 0.60-0.61 at c = 1; the contrast rule identifies the order for c up to about 0.84 (0.74 with a
51.2 GB/s link) and gives "not identified" above. With 51.2 GB/s (one 1,024-bit link) k = 2 falls to 0.61, k = 3
to 0.44-0.45 and k = 5 to 0.30-0.31; with 204.8 GB/s or more nothing falls (T-WIDE). The mirror holds for y first.
The prior: E31-E32 found per-reader bandwidth within 6% between layouts with up to four flows per link (under x
first) and link-disjoint ones, which argues against a 51.2 GB/s link; that E32 average could hide a few throttled
flows, so 102.4 is not excluded. Registered guesses, not decisions: P1, P2, P4-P8 and P12 survive; the link is
about 102 GB/s; P3 is open; no guess about c (a line request is a header against a reply's 64 B, so c is small if
links count bytes, near 1 if they count packets).

## Decision rules (`reduce.py`, thresholds in `params.json` "decision")

- **R31.** Per caller-target pair, the median over every non-warm-up call of every pass. P1 as in the table; if P1
  fails, P2, P3, P5, P6, P6b and P7 are "not decided". **Access-count check** (before P2 and P3): the per-hop slopes
  of pmc 0 - pmc 3 and of pmc 3 - null must agree within max(2 cycles, 15% of the latter), as the compiled
  firmware's one load + one store each predicts; if they do not, the card's firmware does not make those accesses
  and P2 and P3 are "not decided" (both slopes reported). Otherwise P2 and P3 use the pmc 3 - null slope as in the
  table (P2 refuted when it lies in neither interval; P3 then "neither"). P5: shire 32's per-caller medians against
  C + s x hops(caller, cell) with C free, over the four grey cells; the best cell is decided if its rms <=
  max(6, s/6) and the second-best is worse by >= s/3 (a free constant cannot tell cells outside the grid apart, so
  only grid cells are candidates). P6: the 28 cells of the first ring outside the grid, one constant for all eight
  memory shires (iterated to a fixed point from the per-shire free fits); the same rms and margin rule per memory
  shire; P6 is refuted if every memory shire is placed and one is off its firmware cell, and "not decided" if one is
  not placed. Reported, not decided on: the same fits on each pair's 10th percentile (the least disturbed by the
  stats worker), the own-shire offset, the additive model's rms.
- **R32**, per mode: *hold* = rho >= 0.95, *fall* = rho <= 0.90. Negative controls must hold, or the mode is
  "invalid". **x first** if rowE5 and rowF5 both fall and either every column set holds or min(colS5, colN5) -
  max(rowE5, rowF5) >= 0.10; **y first** the mirror; **"wide"** if every family set and both positive controls hold;
  **"not identified"** if a row k = 5 set and a column k = 5 set both fall without that contrast; otherwise
  "ambiguous". T-XY and T-YX: survived for their order, refuted for the other, "not decided" otherwise. T-WIDE:
  survived for "wide", refuted otherwise. T-ADAPT: refuted when an order is identified, "not decided" when not
  identified, "not tested" for "wide". The link's capacity is the median total GB/s of the sets that fell with their
  data sharing the link (positive controls, and the family of the identified order; with no order identified, every
  set that fell). **A write verdict in which no set fell counts only if the writes could fill a link:** for "wide"
  or "ambiguous", the smallest summed solo write bandwidth of the four k = 5 family sets must be >= 1.2 x the
  read-derived capacity (with no read-derived capacity it cannot), otherwise the writes are "not decided". A write
  verdict in which sets fell ("xy", "yx", "not identified") shows that a link filled and counts whatever the demand:
  the request network may be narrower than the reply network.
  P12: survived if both modes identify the same order, refuted if they identify opposite orders, "not decided"
  otherwise. Also reported, not decided on: rho per set and pass, whether rho falls monotonically with k within
  each family (tolerance 0.02), and c (P13).
- **Data kept.** Only launches whose host reported ok (every minion or caller answered, no refused entry, no slot
  overrun, no timeout) and processes whose clock, read just before them, was 600 MHz (a process read off 600 MHz is
  not run at all). An R32 process whose launches partly failed does not drop its pass: only its launches that were
  not ok are dropped. A pass whose block did not end ok (a HALT: any R31 failure, a timeout, missing telemetry, a
  hot die, any smoke failure; or someone else on the card) is not reduced. Nothing else is dropped: no outlier rule beyond the medians. In the dry model the
  median rules still return the planted answers with 25% of ESR calls delayed by up to 600 cycles; at 30%
  memory-shire placement becomes "not decided", and near 35% P1 fails. Development reports the gap between the
  medians and the 10th percentiles, and may raise the repetitions (an amendment) if it is large.
- **Survival.** A theory survives on a card when its rule holds on the pooled passes of that card; the summary lists
  survived / refuted / not decided per theory and per card. The unit of replication is the pass (independent host
  processes and launches); the validation card is aifoundry3 (then aifoundry2 after DV2); a theory is reported as
  holding only if it survives on the development card and on every validation card run.

## Not run: Q63's second test (per hop or per mm)

Q63 asks for hops of another physical length: through a memory-shire column (1.74-1.80 mm wide) against the 3.72 mm
compute tiles. The geometry does not offer one without new routing assumptions. (1) Every shortest path between two
compute shires stays inside the 6 x 6 grid, so compute-to-compute traffic, the only traffic whose per-hop energy was
measured (E27, E31-E32), never enters a memory-shire column, and no minimal route runs along one. (2) Traffic that
does reach a memory shire crosses exactly one grid-edge hop into it on every path, whatever its source, so that hop
cannot be separated from the constant, in energy (where it would sit under 115 pJ/B of DRAM) or in R31's timing
(where it joins the memory shires' constant). (3) The other cells of odd size, the grey PCIe and I/O cells, lie on
some compute-to-compute routes, but only under one routing order (for example shire 3 to shire 28 passes (0,3)-(0,5)
under y first, not under x first), and their physical sizes are not known. After R32 settles the order, a route
through the grey cells becomes possible without an assumption; it would still need those cells' floorplan. So R32 is
the prerequisite, and the test is left for after it.

## Revisions before any data (28 September, after review; no card had run any of this)

1. R31's access counts were taken from `pmu.c`'s text (pmc 0 = 3 loads + 2 stores, pmc 3 = 2 + 2); the compiled
   firmware makes 2 + 2 and 1 + 1. P2 and P3 now use one load + one store per hop, with the access-count check.
2. R32's first rule ignored requests: every family shares a link under both orders (replies under one, requests
   under the other), so "every column set holds" could refute T-XY and confirm T-ADAPT when requests cost as much
   as replies. The order is now read from the contrast; "both families fall" is "not identified"; P13 added.
3. Writes: the power rule above was added, so weak remote stores give "not decided" rather than "wide" (a write
   verdict in which sets fell counts regardless, since the request network may be narrower than the replies').
4. Data kept: per launch for R32 (a failed write path no longer drops a pass's R31 and read data); R31 launches not
   reported ok are dropped; a caller that refused an entry is not ok.
5. The stats worker's background sampling is stated, modelled in the dry run, and reported (10th percentiles).
