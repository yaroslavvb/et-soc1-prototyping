  process inside the sandbox cannot read the `/proc/<pid>/fd` links of a process outside its user namespace (permission denied), while a
  process outside reads an inside process's links as `/dev/et1_mgmt`. So the runner's `--holder-check` is `holdercheck_e198.sh`, which asks
  `warden_e198.py`, running outside, to run the box's own `et-who --check` and hands back its stdout, stderr and exit status unchanged; no
  answer in 28 s is exit 2, which the runner reads as "not free" (never "free" by default). The box's et-who outside lists both cards'
  holders (fuser on `/dev/et0_*` and `/dev/et1_*` and both lock files, by device and inode, so a holder inside the sandbox is listed too).
