### 2.5 Shared chart toolkit: yes

Every source-built page script re-declares the same `el`/`txt`/`host`/`hover`/`axes` helpers, hover works only with a mouse, charts are fixed 700–900-unit viewBoxes forced to 640 px, and at least twenty findings independently ask for the same fixes. One small shared toolkit makes the new charts look and behave alike.

**Files.** `docs/reports/sources/chartkit.js` (vanilla JS, no library, target ≤ 250 lines) and a CSS block added to `report.template.html`. `scripts/build-report.py` inlines `chartkit.js` into the template before `__SCRIPT__` (a new `__CHARTKIT__` placeholder), so `D` and `CK` are both globals for the page script. A new `scripts/paste-chartkit.py <page.html>` copies the same JS, the CSS block and a token-alias block into standalone pages between `<!-- chartkit:begin -->` / `<!-- chartkit:end -->` markers (idempotent; `--check` reports drift). Standalone targets: memory hierarchy, on-chip communication, matmul, sparsity, ridge points, test drive, `workloads/memprobe/report_template.html`, the spatial brief and the L2 brief.

**Tokens.** The kit uses only the template's tokens: series `--c1 --c2 --c3 --c4 --c5 --c7` in that order, `--ref` for reference or neutral marks, `--ink`/`--ink-2` for text, `--grid`/`--axis` for rules, `--surface`/`--page` for fills. **No `--c6` is added** (IA-22). Standalone pages get an alias block (`--c1: var(--et)` etc., plus `--ink`, `--grid`, `--surface`, `--ref`, `--muted` where missing) in all three `:root` blocks (light, `prefers-color-scheme: dark` guarded by `:not([data-theme="light"])`, and `[data-theme="dark"]`). Sequential fills use `CK.ramp(p)` = `color-mix(in srgb, var(--c1) (15 + 85·p)%, var(--surface))`, applied through `style.fill` so dark mode keeps the emphasis; cell text colour is chosen per theme from `getComputedStyle`. Hex colours in page scripts are not allowed in new or touched charts.

### 2.6 Visualisation standard and acceptance checks

Every new or reworked visualisation must:

1. **Answer one question** stated in its title or first caption sentence, and say what it replaces or complements.
2. **Read its numbers from data** (the page's `D`, an embedded JSON block or a value exported by the page's analysis script). Typed literals are allowed only for published third-party constants (A100 spec, FOSDEM rungs), each with a source comment.
3. **Work at 390 px**: no horizontal page scroll; the key feature (the result the chart exists to show) visible without sideways scrolling; rendered text ≥ 11 px; controls wrap; panels stack. Check with `shot.sh <page> <prefix> 390` and read the pieces.
4. **Work from the keyboard**: Tab reaches every control and at least one focusable mark per series (CK.keynav); arrow keys step where the spec says; focus shows the same tooltip or readout as hover; Escape hides; the focus ring is visible.
5. **Work in dark mode**: render once with `document.documentElement.dataset.theme='dark'` and once with the OS preference emulated; no hard-coded colours; marks visible against `--surface`.
6. **Match the data**: the default-state readout, labels or caption contain the "golden numbers" listed in the work order (grep the `render_text.sh` output); and every number the chart prints is computed.
7. **Degrade**: the numbers remain available without JavaScript (the table it complements stays, possibly inside `<details>`).
8. **Pass `check_page.sh` (fixed)**: no load-time errors, no overflow at 1280 and 390, all anchors resolve.
9. **Respect data limits**: no mesh routes drawn (routing order unmeasured); modelled or extrapolated regions labelled as such; "measured" only where it was.
