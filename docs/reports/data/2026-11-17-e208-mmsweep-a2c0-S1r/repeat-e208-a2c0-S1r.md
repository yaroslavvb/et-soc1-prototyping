## Notes (post hoc)

- **Roles:** `arm` runs are read for time and energy; `time` runs for time only (never for energy, by the reducer's rule); the anchor runs 9 times a session. A **capped** run (fewer than 80% of its launches after 1.0 s in the 800 MHz band) is not read for energy; `capped_runs` per arm is in the JSON.
- **The within-session spread** here is the anchor's alone (one arm, high signal, 9 runs spread over the session); a low-signal arm's W over idle varies more in relative terms, which the null runs' sd in watts bounds from below.
- **S2** ran the same 71 arms in the reverse order (blocks and each unit's kinds reversed) between the first S1 and the repeat (19:14-19:53 PST Mon 16 Nov): its differences mix the order with the session.
- **The die corrections:** `J_op_corr` is each session's own registered correction (`dP / (1 + s (die_start - die_ref))`, with the session's own slope and reference: the repeat's and the first S1's references and slopes are in the JSON's `die`), so its differences carry the two references' difference; the post hoc `_c50` columns put both sessions on one reference, 50 C at the registered default 0.48 %/C, so their differences are the measured ones less the die starts' difference at that slope.
- **What a model can be scored to:** a model that knew each arm's value exactly would still differ from one session's reading by the session-to-session spread; for a single-run arm read once, about rms/sqrt(2) of the repeat-first rms above, if the two sessions are equally noisy and independent.
