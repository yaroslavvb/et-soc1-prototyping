# Artifacts: what was published, and where it lives

Three kinds of artifact came out of this work: **published reports** (HTML, deployed to spacesheep.dev),
**repostable images**, and **tools** that can be re-run. Commits are listed at the end so any artifact can be
tied to the state of the tree that produced it. Cite as **A1**...**A19** (A9 and A10 were never assigned):
A1–A5, A11, A13–A15, A17 and A19 are reports · A6–A8 images · A12 math rendering · A16 the rerun tools · A18 the
wire tools. The public index of every report is the hub,
[Limits of observability](https://spacesheep.dev/@yaroslavvb/et-soc1-limits-of-observability#reports) (A2).

Reports A2–A5, A11, A13–A15 and A17 are assembled by `scripts/build-report.py <name> <data.json> <out.html>` from
`docs/reports/sources/<name>.{meta.json,body.html,script.js}` (A2 also keeps its data in
`limits-of-observability.data.json`, whose computed blocks `python3 tools/ettelem/sync_hub_data.py` writes: run it
before `build-report.py`, and again after regenerating any file it reads; `--check` exits 1 if the data file is
stale; A16 lists the blocks). Edit the sources, not the HTML: it is regenerated. A1 is generated by
`python3 workloads/memprobe/build_report.py docs/reports/data/2026-09-19-memprobe-aifoundry2/summary.json
docs/reports/data/2026-09-23-energy-manual/manual.json docs/reports/2026-09-19-et-soc1-memory-anatomy.html` from
`workloads/memprobe/report_template.html` (E1 gives the whole chain): edit the template, not the HTML.
A19 and the four 2026-09-18 reports are hand-written HTML whose embedded JSON is rewritten by their `--embed`
scripts (the commands are in "Rebuilding the standalone pages" below). The 2026-09-18 test drive
(`docs/report/index.html`) is hand-written HTML whose `ladder-data` JSON `scripts/mmbench-report-data.py --ladder`
rewrites; the two 2026-09-22 briefs are plain hand-written HTML (the L2 brief is now a pointer page). For these, edit
the prose in the HTML. Every page with charts carries the shared chart toolkit (A12): the source-built pages get it
from `scripts/build-report.py`, and the standalone pages from `scripts/paste-chartkit.py PAGE`, which refreshes the
marked block and changes nothing else (`--check` reports a missing or stale block).

**Visibility.** Every space the hub links is public (Q40); the one exception, the David Kanter notes, is private and
no longer linked (below). This file is the record: after any deploy, compare `npx spacesheep list` with the
visibility columns here.

## A12 — Math rendered at build time

`scripts/tex2svg.js` turns the TeX in a report body into standalone SVG, called from
`scripts/build-report.py`: display math between `$$`, inline math between `\(` and `\)`, anything inside
`<pre>` or `<code>` left alone. It needs mathjax-full, pinned to 3.2.1 in the repo's `package.json` and
`package-lock.json`: run `npm ci` once at the repo root (3.2.2 gives byte-identical SVGs). In a git worktree without
its own `node_modules`, set `NODE_PATH` to a checkout's.

**Why not the usual runtime MathJax:** the first attempt loaded MathJax from `cdn.jsdelivr.net`, and the
publishing host blocks external scripts in viewers with a content-security policy — the deploy says so. Every
equation would have shown as raw TeX to every reader. Pre-rendering also means the files stay self-contained
and the math is identical in every browser. MathJax colours its SVG with `currentColor`, so dark mode works
with no extra rule.

**The chart toolkit (added 2026-09-25).** `docs/reports/sources/chartkit.js` is one small shared library, no
dependencies, defining the global `CK`: SVG helpers, charts sized to their container (one unit is one CSS pixel, so
text stays legible on a phone), scales and axes, tooltips that open on hover, focus and tap, keyboard stepping over
marks, legends that toggle series, segmented controls, labelled sliders, a live readout, linked views, stacked
tables for narrow screens, and colours taken only from the page's theme tokens so dark mode keeps its contrast.
`scripts/build-report.py` inlines it into `report.template.html` at `__CHARTKIT__`, just before the page script, and
its CSS sits in the template between `chartkit:css:begin` and `chartkit:css:end`. Standalone pages get the same JS,
the CSS and an alias block mapping their own token names onto the kit's through `scripts/paste-chartkit.py PAGE`
(between `<!-- chartkit:begin -->` and `<!-- chartkit:end -->`; `--check` reports drift). Its API is in PLAN2 §2.5
(`docs/reports/data/2026-09-24-report-review/PLAN2.md`).

## Publishing notes, learned the hard way

- Deploy with `npx --yes spacesheep deploy <file-or-dir> --space <uuid> -m "<message>"`. **Always pass
  `--space`** when updating, or the CLI creates a new space.
- **Deploy A4 as its folder, never as a single file.** The GIFs (A6–A8) are part of that space, and a single-file
  deploy drops them (it happened on 2026-09-24; the folder was redeployed the same day).
- A folder deploy (`index.html` plus assets, which is how A4 ships its GIFs) has **changed a space's
  visibility in both directions**. Run `npx spacesheep list` after every deploy and fix it with
  `npx spacesheep share <uuid> --visibility public|private`. The visibility column above is a snapshot, and
  visibility is the repo owner's call, not the deploy script's.
- **Delete any `.spacesheep.json` the CLI leaves behind, every time.** It pins a folder to a space, and
  `deploy` uses it when `--space` is absent. On 2026-09-22 a stale `docs/reports/.spacesheep.json` from the
  DVFS brief silently published the hot-line report **over** that brief. The recovery is to remove the pin
  file, redeploy the right HTML with an explicit `--space`, and check the published `<title>`. Safest habit:
  deploy a new report from a directory of its own, and always pass `--space` for an update.
- A new space is private and gets its slug from the file or folder name. Pass `--title`, `--slug`, `--emoji`
  and `--description` on the first deploy, or fix them on the next one; all four are kept on later updates.
- **On an update, `--title` without `--slug` re-slugs the space.** On 2026-09-24 the review's redeploy passed
  new titles and every one of the 18 spaces moved to a slug made from its title (the old URLs went to a sign-in
  page) for about seven minutes, until each was redeployed with `--slug <old slug>`. Pass the existing `--slug`
  whenever you pass `--title`, and check `spacesheep list` for the URLs afterwards.
